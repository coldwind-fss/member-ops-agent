## 1. 产品定位与范围

以小型自营运动品牌的会员社群为需求原型。服务一个品牌、一位运营、两个会员群，典型规模为几十至几百名会员。产品帮助会员在原消息渠道解决商品、订单和活动问题，也让运营能接手例外、跟进未满足需求、执行活动并复盘。

交付形态为独立运行的 Agent 服务和运营后台。会员体验通过原渠道呈现，运营在后台配置与处理事项。公开仓库使用独立源码和虚构业务数据，真实微信和商家接口的可用性通过实际授权和联调确认。缺少外部依赖时，通过测试替身验证约定的业务行为，并分别标明已实现、已验证和已接入的范围。

| 角色 | 主要职责和权限 |
| --- | --- |
| 会员 | 询问公开资料，核验身份后查询本人的业务信息，参加活动，订阅或取消提醒，提出人工请求和本人记忆更正 |
| 运营负责人 | 唯一运营角色。维护资料、活动与触达规则，查看必要业务信息，确认画像与发送计划，处理异常和售后 |
| 助手 | 根据明确触发处理问答和运营动作，记录依据与结果，按规则转人工。退款、赔付、改订单、额外优惠等决定归运营及相应业务系统 |

范围外包含模拟会员群产品页面、多品牌多租户、复杂客服分派、完整商城支付仓储、自动退款、积分商城、分销返佣和大型裂变活动。后台活动支持轻量报名、打卡和问卷。

## 3. 共享业务规则

### R01 消息入口、参与者和事项

1. 会员明确 @ 助手，或明确回复助手并继续提问，进入会话处理。普通聊天进入有授权的群分析范围。消息相邻、仅转发或引用他人发言、单纯附和均不构成执行请求。
2. 短期事项按群、发起会员和事项区分。优先使用明确回复关系及对象。无明确引用时，仅当该会员在该群只有一个兼容事项且指代清楚，才延续。存在多个可能对象时先询问。一个会员的导购和售后分别处理。
3. 不同会员可以引用同一公开商品或活动。公开引用只提供话题，不提供另一人的预算、偏好、身份、权益或订单。并发结果按各自的原始请求回复，完成顺序不改变回复目标。
4. 重复收到同一消息时复用已有结果或等待状态。会员主动再次提出问题时，先判断是否为同一事项，再决定追加、重新查询或新建。
5. 当前事项转人工后，新的补充信息追加给该事项。该会员的其他事项和同群其他会员正常服务。
6. 单次服务的结果分为已答复、等待补充、转人工、无法处理。事项可处于进行中、等待会员、人工处理、结束。普通事项默认在连续 24 小时无互动后退出默认上下文。明确引用旧事项时重新核对变化事实，再决定恢复。人工待办和订阅独立保留至业务完成或取消。

### R02 意图识别、对象解析与业务授权

会话先判断是否响应，再确定当前事项，识别会员想做什么以及涉及的对象，最后由业务规则决定是否能执行。定时、补货、签收等事件根据事件类型进入指定流程。话题、会员身份和业务权限分别判断。分类结果应能追溯到用户表达及当前事项。

| 意图 | 示例 | 去向与判断 |
| --- | --- | --- |
| 公开知识 | 「这款怎么洗」 | F03。解析款式，查询有效资料 |
| 选购与商品状态 | 「跑步选哪个」「还有黑色吗」 | F04。区分比较推荐和实时规格库存 |
| 个人业务查询 | 「我那单到哪了」「我有没有券」 | F02、F05。验证本人身份和归属 |
| 公开活动与优惠 | 「今天的券能叠加吗」 | F05。检查生效状态和适用规则 |
| 参与活动 | 「帮我报名」「这是我的打卡」 | F06。核对明确请求、活动资格和重复提交 |
| 订阅与取消 | 「XL 有货告诉我」「不用通知了」 | F13。确认目标规格、本人身份和明确意愿 |
| 一般售后规则 | 「退换规则是什么」 | F03。按公开规则答复 |
| 特殊售后、投诉或明确找人工 | 「收到就开胶了」「给我找人工」 | F14。明确请求人工时立即交接 |
| 偏好更正或删除 | 「别再记我的尺码」「我现在穿 XL」 | F07。校验本人和对象，确认必要范围 |
| 无关或无法识别 | 多义指代、普通闲聊 | 被明确询问时澄清。普通闲聊仅按 F15 判断是否可分析 |

一条消息可以含多个诉求。互不依赖的咨询分别记录和处理。带前提的请求先验证前提，例如「如果寄错了再找人工」。明确要求人工或明确投诉优先处理对应事项。缺少必要条件时每次聚焦一个问题，连续两次澄清仍无法推进时，说明障碍并提供人工选项。会员明确要求人工时无需等待两次澄清。执行资格以身份、权限和实际业务状态为准。

### R03 上下文与记忆取用

| 信息 | 读取边界 | 权威来源与写入结果 |
| --- | --- | --- |
| 群公共话题 | 当前群明确引用的公开商品、活动和消息 | 记录引用关系。仅用于理解话题 |
| 当前事项 | 当前群、会员及事项相关消息、临时条件、已查结果 | 保留本事项所需信息。代购尺码和当次预算不沉淀为本人长期偏好 |
| 品牌知识 | 和当前商品、规则、地区或时间相关的有效内容 | 以运营发布的有效版本为准，保留依据和版本 |
| 实时业务信息 | 涉及当前库存、价格、订单、物流、个人优惠时查询 | 以授权业务源为准。旧结果供回看，新问题涉及变化事实时重新查 |
| 长期会员记忆 | 已确认身份下与当前任务相关的偏好、事实事件、需求和订阅 | 最新明确纠正覆盖旧偏好。当前条件优先用于当前事项，推测不能覆盖事实 |
| 任务状态 | 当前事项、订阅、活动任务及人工待办 | 决定继续、等待、交接、取消或结束。不同事项各自记录 |
| 群分析证据 | 有权限的群消息、活动结果和时间范围 | 群级聚合保留在群复盘。只有可归属个人并可核对证据的信号进入个人候选记录 |

身份未验证时只使用当前渠道身份、公开内容及其当前事项。两个群里名称相同的用户保持独立。身份明确关联后，可以按用途读取该会员的长期信息。个人事项默认留在发起渠道，跨群继续需要明确引用并核对身份。群内可回复公开规则与处理引导。订单、地址、个人资格、联系方式和私人历史通过授权的私密入口处理。向运营传递解决当前事项所需的最小信息。

### R04 来源、结果与降级

- 来源缺失、版本冲突、权限不足、接口未配置、暂时失败、查询为空分别记录和展示。缺失的数据源不能作为事实。对用户说明当前能确认的内容以及下一步。
- 同一查询的业务结果、回复是否发出、会员是否确认解决分别记录。对外动作按计划、待执行、已受理、已发送、已送达、失败、待核实、取消或过期记录。只有对应证据可用时才升级结果。接口返回受理只能确认受理。
- 同一对外任务按事件、目标、计划或订阅和动作识别重复执行。发送结果不明确时进入待核实。核实前保留任务，避免重复发送。运营触达明确暂时失败且仍符合条件时，允许在有效期内自动重试一次。重试须重新校验活动、订阅和渠道。再次失败进入工作台，由运营决定是否手动重试。
- 发出动作前以最新有效的取消、退出和暂停状态为准。已经实际发出的动作保留结果。晚到的业务事件可补全历史记录，不能恢复已取消或过期的任务。
- 历史记录可用于经允许的复盘和画像。欢迎、签收、补货等面向会员的动作由启用后收到的有效事件或运营明确创建的任务触发。

## 4. 会话、查询与活动业务流

| 流程 | 触发和输入 | 业务动作、停止及记录 |
| --- | --- | --- |
| **F01 会话接入与分流** | 明确 @、回复关系或渠道提供的请求。输入发送者、群、原消息、引用和事项状态 | 按 R01 确认是否接入。按 R02 解析意图、对象及依赖关系。确定公开答复、私密办理、澄清或转人工。记录消息归属、意图、流转和回复目标。例外按 R04 结束或等待 |
| **F02 身份验证与个人查询** | 查本人的订单、物流或权益。输入渠道身份、已绑定会员、业务对象 | 未绑定时提供商家可用的身份验证入口。私密入口不可用时提供已配置的官方服务入口或建立人工待办。已验证时检查对象归属，多笔结果在私密渠道澄清。无权限只说明无法查询，避免透露第三方对象是否存在。记录查询类别和来源，成功给结果，异常给下一步 |
| **F03 品牌问答与规则解释** | 公开商品、品牌、保养、配送或通用售后咨询。输入问题、引用对象和有效知识 | 确认对象，查询适用资料，给出有依据的答复及必要入口。图片能读取时作为本事项资料，型号不清时向会员补问。规则缺失或冲突时记录知识缺口。有明确未解决需求时按 F14 处理。结束本轮并记录依据 |
| **F04 导购与实时商品状态** | 选购、比较、规格或库存咨询。输入用途、预算、规格、相关本人偏好与当前商品数据 | 先补齐影响推荐的关键条件。比较时说明适用与限制。颜色、规格、库存、价格按当前数据回答。缺货时可询问是否订阅，只有明确同意才进入 F13。记录条件、推荐依据和需求，不把临时条件写成长期偏好 |
| **F05 活动、优惠与资格** | 咨询时间、门槛、叠加、适用商品或本人资格。输入有效活动、当前规则和需要时的已验证身份 | 先区分公开规则和个人资格。查有效期与适用条件，公开说明可在群里回答，个人资格走 F02。结束活动明确说明。规则与实际业务状态冲突时，给可核实入口或转运营确认。记录活动版本和处理结果 |
| **F06 报名、打卡与问卷** | 明确报名或提交。输入活动、会员、提交内容、时间和已有参与记录 | 校验活动开放、参与资格和提交规则。通过可用渠道登记。问卷及私密材料经适当入口提交。默认每个会员每场活动一条报名，每周期一次有效打卡，每问卷一份有效提交。重复回传已有结果。默认关闭补打卡及提交后修改，由运营在活动开始前启用。活动结束停止接收并记录参与和进度。活动支持轻量进度汇总 |

活动由运营创建草稿并发布。发布前确认时间、资格、群范围、参与入口和提交规则。发布后到达开始时间才接受参与。暂停时保留已有参与记录并停止新提交，恢复时继续按有效期处理。取消或结束后停止提交及关联待发通知。已有参与者受影响的资格、时间或规则变更，由运营确认适用范围后发布，原记录保留对应版本。

## 5. 会员经营、运营计划与触达业务流

### F07 会员记忆的建立、修正和退出

- **触发与输入**：会员明确表达长期偏好或需求，发生实际咨询、报名、交易或服务事件，或会员和运营提出更正。读取经确认身份、证据、时间、适用范围和已有条目。
- **处理**：本人明确偏好与可靠事件按规则记入。推测生成候选标签，保留依据和有效期，运营确认后可用于基于该标签的触达筛选。一次随口询价、沉默和群体趋势不直接成为强意向。明确需求与订阅分别记录。
- **更正与删除**：验证会员或运营权限。更新或删除后立即从默认读取和筛选中移除旧条目，复查相关待发任务。历史原文按其自身保存规则处理，已删除证据不会被历史复盘重新沉淀为同一记忆。删除档案、解除绑定或取消订阅时，按受影响范围停止相关待执行的个人动作。
- **停止与记录**：记录写入、更正、删除、失效或不保存的结果。保留最少的变更证据及时间。历史记录中的临时条件在当前事项结束后退出默认读取。

### F08 画像、筛选与目标人群

- **触发与输入**：运营打开会员经营或创建定向计划。读取归属群、互动时间线、明确偏好、已确认标签、候选信号、订阅和未完成事项。
- **处理**：会员列表支持按群、近期互动、兴趣、未满足需求、参与和订阅筛选。详情展示明确事实、实际行为、推测意向、待办和订阅。运营可以查看原始依据、确认或移除标签。人群预览展示命中人数、名单、入选及排除原因。
- **停止与记录**：保存为候选人群或产生跟进待办。运营确认名单和用途后才可关联到定向计划。执行时重新核验资格，自动剔除退出、取消或不再符合的人。新进入的人需重新预览确认后才加入原已批准计划。记录筛选条件、确认名单和实际执行对象。

### F09 活动运营与定时触达

- **触发与输入**：运营创建或修改活动计划。输入活动规则、有效期、目标、文案、计划时间、渠道和频率。
- **处理**：助手按有效资料生成草稿。运营确认内容、对象和时间后排期。涉及内容、目标或时间的修改重新确认。执行前检查活动状态、实际权限、取消、暂停、资格和频率。群公告给整个目标群。个人计划走允许的私密渠道。无私密渠道时生成个人待办。
- **停止与记录**：发送、转待办、取消、失败或过期。取消活动后终止对应待发任务。记录计划版本、目标、尝试与实际结果。发送结果未知时先核实。

### F10 新人接待

- **触发与输入**：启用后收到真实入群事件。输入群、成员、当前群成员状态、有效欢迎文案和欢迎历史。
- **处理**：检查该群已启用、成员仍在群、同一成员在同一群 24 小时内未成功执行欢迎。用预先确认的简短文案介绍咨询方式和群用途。批量加入时按渠道规则合并欢迎。失去成员资格或入群已超过 24 小时则取消。
- **停止与记录**：记录入群事件、目标群、欢迎结果及频率跳过原因。历史导入及重复回传仅用于记录，见 R04。

### F11 购后关怀

- **触发与输入**：启用后收到可信签收事件，或运营按已核实信息创建任务。输入会员、订单商品、实际状态、当前使用保养资料和触达条件。
- **处理**：使用预先确认的流程。默认签收后下一可用工作时段安排一次关怀。发送前复核是否已退货、取消、出现相应售后或会员不希望接收。符合条件且渠道可用时，提供商品相关说明。否则跳过或转待办。没有可靠签收依据时由运营安排。
- **停止与记录**：每订单同一关怀计划执行一次。记录状态、商品资料来源和实际结果。收到售后反馈转 F14。

### F12 意向跟进

- **触发与输入**：明确未满足需求或有证据的购买意向。输入原表达、对象、会员状态和近期互动。
- **处理**：助手生成带依据的跟进建议。运营确认是否联系、用哪个渠道以及沟通内容。随口询价可进入候选信号。自动提醒资格由独立订阅或运营批准的计划判断。
- **停止与记录**：已解决、明确拒绝、已经购买或意向失效时结束。记录运营选择、结果和实际证据。

### F13 补货订阅与取消

- **触发与输入**：会员明确请求某商品规格的到货提醒、明确取消，或库存源提供补货事件。输入已验证会员、商品及规格、订阅状态、当前库存和可用渠道。
- **处理**：确认规格与通知意愿后登记，同一会员同规格只保留一条有效订阅。补货时逐一检查订阅有效、目标规格确实有库存、渠道可用且尚未完成此次提醒。无可用渠道时生成一条运营待办。取消时取消待发提醒及尚未处理的对应补货待办。发送或人工联系前再次核实。
- **停止与记录**：明确发送成功、运营确认已通知、取消或到期后结束本次订阅。失败时保留订阅并按 R04 判断能否重试。过期或退订后可重新订阅。记录请求来源、匹配规格、触发事件和处理结果。


## 6. 人工协作、复盘与系统管理业务流

### F14 转人工和售后跟进

1. **触发**。会员明确要求人工，出现明确投诉或质量售后，涉及退款、赔付、改订单等决定，或者助手用完澄清与查询路径后仍有未解决需求。一般规则问答继续由助手处理。知识缺口没有待解决的会员事项时，进入 F16 的纠错队列。
2. **建立或追加待办**。依据当前群、会员和事项去重。保存原问题、转交原因、已查结果、还缺什么及原消息入口。通知只给唯一运营负责人。默认使用已配置的个人邮件，后台同时出现待跟进事项。邮件未配置或失败时，待办仍可见。
3. **与会员沟通**。登记后可说「已登记」。有成功发送证据时可说「已通知运营」。尚无人处理时说明工作时间和后续安排。明确投诉和要求人工的事项交由运营接话。其他事项仍由助手响应。
4. **处理与收尾**。后台仅显示「待跟进」「已处理」。运营收到提醒后可直接回原群，或通过授权私密渠道联系会员。补充消息追加到同一待办。运营填写结果并标记已处理。需要助手继续时，运营明确提交确认结果并交回，助手重新校验变化事实再回复。新的未解决情况可重新打开原待办。
5. **通知规则**。紧急投诉和明确请求人工在工作时间即时提醒。其他新待办同样通知负责人，同一事项只发一次初始提醒。工作时间外先登记，下一工作时段提醒。通知明确失败可在工作时间自动重试一次。仍失败或发送结果不明时在工作台标记。超过一个工作日仍待跟进，汇入下次工作台提醒，避免每次会员追问都再通知。
6. **结果口径**。待办已处理、通知已发送和会员确认解决分别记录。人工完成商业动作时记录运营提供的结果或对应业务引用。

### F15 群分析、预警与复盘

- **触发与输入**：允许分析的群消息出现投诉、重复疑问、购买信号或未解决事项，或到达日报生成时间。读取群、时间窗口、原始证据、服务和活动结果。
- **处理**：按群与主题归并重复信号。明确需要人工的投诉进入 F14。其余生成摘要或跟进建议。个人画像信号需要可确认的会员归属与原始证据。普通分析结果进入后台，群内公开回复继续遵循 R01。
- **停止与记录**：运营可确认、纠正或关闭信号。日报按群展示咨询主题、未解决事项、商品反馈、活动进度及相关依据。默认每日汇总可获得的事件。原证据过期时标明不可回看。无权限、无数据或数据不完整时标明范围。
- **使用结果**：运营可从复盘进入原事项、补 FAQ、更新活动说明，或将可核对的个人信号送入 F07–F08。

### F16 知识发布、纠错与业务验证

- **触发与输入**：运营新增资料、发布新规则、纠正一条回答，或处理分析发现的知识缺口。读取原问题、答案、引用版本、确认的正确口径和适用范围。
- **处理**：将问题区分为资料缺失或过期、理解错误、查询失败、权限或流程错误。资料修订进入草稿，运营确认适用对象及生效时间后发布。规则同范围冲突时由运营确定有效版本。在冲突解决前，对外说明当前无法确认并提供下一步。
- **停止与记录**：知识条目保留版本、生效范围和发布历史。旧回答保留当时所用依据。修正后用原问题和典型变体验证，记录实际结果。错误回答和模型推测进入候选纠错材料，发布权由运营持有。

### F17 启动、暂停、恢复与运行检查

- **启动**：配置唯一运营、允许的群、资料及渠道能力。按群启用公开应答、群分析和运营触达。群分析只读取授权范围。自动计划在运营确认配置后启用。缺少个人查询、发送或通知能力时，工作台标明受影响功能并按相应流程降级。
- **暂停**：运营可按群暂停自动应答或运营触达。暂停期间保留后台待办、已有记录和运营手动处理入口。需要停止读取和分析时关闭对应群的分析开关。正在生成的回复或待发送任务在对外发出前检查是否已暂停。
- **恢复**：复核积压任务的有效期、取消状态、订阅、渠道和频率。原定时间已错过的活动推送由运营确认是否重排，过期任务结束。暂停期间积压的旧咨询供运营查看，会员的新提问可重新启动事项。有效订阅按当前状态核实后继续。
- **运行检查**：按事项查看意图和流转、引用资料、业务查询状态、发送、交接和最终结果。运营可定位异常并重试允许重试的动作。结果待核实时先查原任务，规则见 R04。记录配置变化、可观察的运行耗时、失败原因及费用来源，外部缺少费用数据时标明缺失。

## 7. 业务对象、数据生命周期与外部依赖

### 7.1 对象关系和数据责任

| 业务对象 | 核心关系与生命周期 | 事实来源 |
| --- | --- | --- |
| 品牌、群、群成员、渠道身份 | 一个品牌管理两个目标群。渠道身份属于具体渠道，可在核验后关联到一个品牌会员。群成员资格按群管理 | 渠道、商家会员系统及运营配置 |
| 消息、会话事项 | 消息有来源、发送者、群或私密会话、引用与时间。事项有发起会员、相关消息、对象、状态和处理方。可并行存在多个事项 | 渠道消息及产品处理记录 |
| 品牌知识、商品与订单引用 | 知识按版本与有效期管理。引用指向业务对象，查询结果保留必要信息和来源 | 运营发布的资料，商家商品、订单、库存和物流系统 |
| 会员、行为、记忆、标签 | 一个会员可以关联多个经核验的渠道身份、行为和记忆。推断标签附证据、状态与有效期 | 会员明确表达、业务事件、运营确认与标注后的推测 |
| 活动、规则、参与记录 | 活动包含时间和参与规则。每次提交关联活动、会员及周期。参与或成交只根据实际结果登记 | 运营维护的活动规则及实际活动或交易事件 |
| 需求、订阅、候选人群 | 需求可产生订阅或待办。订阅绑定会员和具体商品规格或目标。候选人群保存筛选条件和批准范围 | 会员明确操作、画像证据、运营确认 |
| 运营计划、任务、触达记录 | 一项计划可以生成多个任务。任务关联事件或计划、目标、状态和执行记录。发送状态和会员反馈分别记录 | 运营配置、实际业务事件与渠道结果 |
| 人工待办、提醒、处理结果 | 待办归唯一运营，关联一个事项，可附多条补充消息。通知和结案有各自状态 | 助手的交接记录、渠道发送结果、运营处理记录 |
| 群反馈、复盘、纠错、验证 | 关联群或事项、资料版本、来源证据、修正内容和验证结果 | 原始消息、业务结果与运营审核 |

### 7.2 身份、成员资格和信息保留

1. **绑定与解绑**。会员走品牌提供的核验入口绑定。姓名、头像或群昵称相同仅供运营辨认。身份冲突时暂停个人查询及画像合并，待运营核实。解绑后停止使用该关联身份做个人查询和定向触达，并复查待执行任务。原业务记录按保留规则处理。
2. **退群与停用**。退出某群后，从该群成员筛选和待执行群内个人动作中移除。会员在其他群的成员资格独立判断。仅在订阅仍有效、渠道允许并符合原授权时，继续与退群无关的私密提醒。会员停用、明确退订或关闭相应联系许可时停止对应个人触达。
3. **资料与可见性**。公开知识按有效版本使用。个人档案仅供本人相关服务和授权运营处理。非必要地址、电话、订单明细等留在授权业务系统。群回复、提醒及日志只带必要内容。
4. **默认保留**。原始消息和短期上下文默认保留 90 天，已完成的业务处理与运营记录默认自结束起保留 365 天，已确认偏好在会员档案有效期间保留至纠正、删除或失效。尚未完成的售后或订阅保留必要处理摘要。原文到期按规则清理，依据入口可显示已到期。具体期限可按部署配置调整。
5. **纠正、删除及历史**。删除画像条目时，将其从当前画像、筛选和回复中移除，取消依赖该条目的待执行动作。原消息和已经发生的处理历史独立保存至各自到期。请求删除原文或档案时按适用对象处理，移除可识别内容并仅保留必要的变更事实。旧证据重新进入分析时不得自动恢复已删除记忆。

### 7.3 外部能力与缺失时的产品表现

| 外部能力 | 依赖的数据或动作 | 不可用时的业务表现 |
| --- | --- | --- |
| 微信或其他消息渠道 | 可用的入站消息、发送者和群标识、引用、入退群事件、公开回复或私密发送能力 | 按实际能力启用。缺少事件时对应自动计划等待或由运营手动创建。缺少发送能力时保留待发状态或转待办 |
| 会员与身份核验 | 已验证的身份关联、本人资格与群成员状态 | 继续提供公开咨询。个人查询给可用核验入口或转人工 |
| 商品、库存、价格 | 商品与规格、当前价格库存、补货事件或可验证变化 | 只提供有依据的静态说明，标明动态结果不可用。订阅保持待触发 |
| 订单与物流 | 本人订单归属、状态、发货、物流、签收 | 明确区分权限、无结果和外部失败。提供官方入口或转人工。无签收依据的购后计划等待或由运营安排 |
| 活动、优惠及权益 | 当前规则、有效期、商品适用性、个人资格 | 公开规则按有效资料说明。个人资格无法核实则给入口或转运营 |
| 运营通知 | 向唯一负责人发送提醒，获得实际发送结果 | 后台保留待办、失败及待核实状态。运营可从工作台处理 |

这些边界定义业务输入、结果和降级行为。实际渠道权限、身份验证入口、字段契约和对接方式在技术基线及接入工作包中确定。

## 8. 验收标准与运营结果

| 验收 ID | 关联规则 | 可观察的通过条件 |
| --- | --- | --- |
| A01 | F01、R01、R03 | A、B 同群分别问同款的尺码和库存，结果先后返回也分别回复原问题，只共享明确的公开商品引用 |
| A02 | F01、R02 | 普通附和不触发回复。引用对象不清时追问。带条件的人工请求按条件处理，明确要求人工直接交接 |
| A03 | F02、F05 | 未绑定会员可问公开问题。输入他人订单号时不泄露对象。接口不可用与查无结果的回复可区分 |
| A04 | F03–F05、F16 | 通用回答引用当前有效资料。历史活动已结束时按当前状态回复。资料冲突、实时接口失败及图片型号不清分别走正确分支 |
| A05 | F04、F07 | 临时为朋友买 M 码只用于当前事项。本人偏好更正、删除后影响后续回答。跨会员不会串用记忆 |
| A06 | F07–F08、F13 | A 询价进入候选人群，B 主动订阅进入有效订阅。B 发送前取消时任务停止。重复补货事件不会重复通知 |
| A07 | F06 | 报名和每周期打卡按规则去重。活动结束后的提交得到实际结果，进度统计可核对 |
| A08 | F09–F13、R04 | 取消或过期活动不发。未知发送结果先核实。未确认的新会员不会自动加入已批准的人群。欢迎和关怀不会因导入历史记录触发 |
| A09 | F14 | 唯一运营收到必要上下文，无需认领。通知失败仍可从后台接手。同一事项连续追问只有一条待办。接管只暂停相关事项 |
| A10 | F15–F16 | 运营能从重复疑问定位原始依据、纠正个人信号并发布有效资料。新回答使用新版本，旧记录可追溯 |
| A11 | F17、R04 | 暂停时不执行对应自动动作。恢复后旧活动和已取消任务不会补发。订单接口故障时公开知识问答仍可正常服务 |
| A12 | 7.2、F08 | 解除身份关联或退出目标群后，相应个人查询和待执行动作更新。删除画像后旧证据不会自动重建同一条记忆 |

运营查看咨询量、实际答复、转人工数、待跟进与处理耗时、有效触达结果、活动参与和知识纠错。分母以指定群、时间和纳入统计的事项为准。同一事项的重复消息不当作新增事项。会员确认解决、运营标记已处理和发送接口受理分别统计。购买和活动转化以能够验证并关联的业务事件计入。缺少真实业务数据时展示测试结果或数据缺失状态。
