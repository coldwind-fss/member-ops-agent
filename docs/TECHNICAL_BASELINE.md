## 1. 运行与模块边界

单仓、模块化后端、API 与 Worker 两个 Python 进程，共用本机 PostgreSQL。Vue 后台开发服务器把同源 API 路径代理至 FastAPI。普通启动只监听回环地址。PostgreSQL 用宿主系统服务，Python 用项目虚拟环境，Node.js 运行 Vue 开发服务器。运行脚本与生产部署配置随工作包确定。

| 模块 | 负责 | 依赖约束 |
| --- | --- | --- |
| 运营后台 | 登录、会话查询、人工待办、品牌知识、会员与活动等页面 | 仅访问后台 API。写操作处理权限、表单错误及版本冲突 |
| API | 运营接口、开发事件入口、实际接入后的供应商回调入口、输入校验 | 路由调用应用服务。回调验证来源，持久接收后应答 |
| 应用服务 | 事项、身份、知识、画像、活动、订阅、接管与触达规则 | 业务状态和事务在这里。由 API、Worker、Agent 工具复用 |
| Worker | 持久任务领取、事件分流、模型执行、计划触发、外部发送与恢复 | 调用应用服务和适配器，领取时段与网络调用分离 |
| Agent | LangGraph 会话图，LangChain 的模型、结构化输出、检索和有限工具循环 | 读取授权上下文，经应用服务获取业务事实或提交动作。图节点可单独验证 |
| 基础设施 | PostgreSQL 持久化、数据库迁移、DeepSeek 客户端、外部适配器 | 供应商 SDK、鉴权与协议翻译集中在这一层 |

前端采用 Vite、Vue 3、Element Plus 和 npm，后台在单页中切换业务面板。Python 使用 SQLAlchemy 2 的异步接口、psycopg 3、Alembic 和 Pydantic。仓库提供 Python 与 npm 锁文件。前端用短轮询更新待办状态，PostgreSQL 任务表支撑调度。组件与迁移参考 [Element Plus](https://element-plus.org/en-US/guide/installation.html)、[SQLAlchemy](https://docs.sqlalchemy.org/en/20/)、[Alembic](https://alembic.sqlalchemy.org/en/latest/)。

## 2. Agent 流程、上下文与模型

### 2.1 F01 到图节点

| 顺序 | 输入与动作 | 结果及边界 |
| --- | --- | --- |
| 1. 接收和筛选 | 验证事件来源，规范化消息，按来源与事件键去重。依据结构化 @ 和回复关系判断是否进入会话 | 输出新事件、重复事件或仅供获准分析的事件。平台 ACK 和模型推理分离 |
| 2. 找候选事项 | 从可信发送者、会话、明确引用及同群同会员的活跃事项中取候选摘要 | 形成允许引用的公开对象与本人候选事项。未核验身份时只用渠道身份和当前事项 |
| 3. 意图识别 | 独立 LangGraph 节点通过 LangChain 调用 DeepSeek，输入当前消息、允许的引用和候选摘要，输出结构化意图 | Pydantic 校验意图枚举、条件、证据、候选引用与缺失项。输出为空、超时或格式非法时在时限内最多重试一次，再走澄清或人工入口 |
| 4. 确认事项和分流 | 校验候选事项归属、当前状态和版本，判断新建、继续、澄清或人工 | 从应用分支表选业务流。明确人工请求和需人工判断的投诉走 F14，带条件的交接先验证条件 |
| 5. 取数和组织回复 | FAQ 查有效资料，订单和权益经过身份与归属校验，导购按需查商品。应用按场景裁剪上下文 | 初始工具循环预算为每次执行最多 4 次调用，可配置。澄清次数沿用产品 R02。模型输出内容与动作建议，业务规则校验后提交 |
| 6. 持久化和交付 | 写回复草稿、引用、处理结果或待办。发送前再次核验事项、渠道及可见范围 | 状态和任务在应用事务提交。对外发送由 Worker 交付，回填实际结果 |

候选定位先于模型，最终事项归属在模型之后确定。首版按渠道、会话和发送者的处理键保持接收顺序。不同会员并行。每个已确认事项只允许一个有效执行者。图线程使用独立事项 ID，回复目标使用原消息和渠道返回的可靠标识。进程失效恢复时，以应用状态与当前版本重建执行边界。

DeepSeek 采用官方 API，模型名称和调用参数由配置提供。语义识别使用 JSON 输出和应用层模式校验，固定意图清单与例子按提示词版本管理。模型对引用、证据、动作等字段提出建议，应用校验这些值是否存在且可读。权限及数据归属来自业务服务。首个工作包实测模型别名、空输出、超时及工具调用。图片能力单独做能力校验，不可用时向会员索取型号或文字。参考 [DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)及[LangChain DeepSeek 集成](https://docs.langchain.com/oss/python/integrations/chat/deepseek)。

### 2.2 数据与执行状态

| 数据 | 权威位置 | 使用和清理 |
| --- | --- | --- |
| 事项、消息、人工待办与任务 | PostgreSQL 应用表 | 记录原请求、处理方、阶段与版本。按产品保留期清理原文与已结案记录 |
| LangGraph 执行快照 | PostgreSQL checkpointer，独立表集 | 仅持久化恢复所需状态、引用和最少信息。应用状态主导授权、暂停和交接。删除、解绑、过期按范围清理快照和派生索引 |
| 会员档案、长期记忆、标签及订阅 | PostgreSQL 关系表 | 存来源、范围、有效期、纠正和删除状态。组装上下文时按身份、事项和用途检索。动态数据沿实时接口查询 |
| F03 品牌知识问答，两步 RAG | PostgreSQL 版本化知识条目 | 先按商品、别名、分类与关键词检索有效资料，再将命中内容交给 DeepSeek 生成答复。记录条目版本和证据。用中文验收样例衡量召回后再评估 pgvector |
| 商家订单、库存、优惠及会员身份 | 外部业务系统 | 本系统保存引用、结果类别和必要查询摘要。敏感详情限制在授权入口 |

WP02 在意图结果中增加商品、规格、用途、活动和订单等可选槽位。目录、库存、公开活动通过 LangChain 只读工具接入两节点 LangGraph，应用限定本轮查询次数及停止条件。订单和个人资格通过验证后的业务服务查询，个人查询结果由应用渲染。私密发送只向匹配的渠道会话投递，在落库与开始发送前校验绑定版本。详情中的业务依据保留来源、结果、时间和必要公开引用。

运营直接接管时创建待办并结束当前图执行。仅在运营补一个结果后由助手继续时使用 interrupt 与 resume。恢复节点可能重新执行，所有业务写入走带稳定操作键的应用服务。定时提醒、报名去重及订阅复查走确定性业务服务。知识文本、群消息和工具输出作为数据处理，命令和身份校验仅来自可信应用路径。参考 [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)及[暂停与恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)。

## 3. 数据库事务和并发

采用 PostgreSQL Read Committed，关键状态转换使用行级锁或版本条件更新，唯一性由数据库约束。事务由应用服务持有，API 路由、图节点和数据库访问层复用同一边界。外部模型、渠道、商家 API 和邮件调用放在短事务外。涉及多行时统一锁顺序。对于可重放的纯数据库事务，死锁等暂时冲突按有限预算重试，跨网络动作独立核实。参考 [PostgreSQL 事务隔离](https://www.postgresql.org/docs/current/transaction-iso.html)及[行锁与队列领取](https://www.postgresql.org/docs/current/sql-select.html)。

| ID | 一起提交的内容 | 冲突与恢复 |
| --- | --- | --- |
| TX01 收件 | 入站事件、规范化消息或事件索引、首个处理任务 | 来源连接和外部事件键唯一。相同事件复用回执，键相同而规范化内容冲突时拒绝并记录。提交成功后返回已受理 |
| TX02 定位事项 | 处理键序号、消息与事项关联、事项状态或版本 | 同一处理键按持久接收序处理。候选版本改变时重新定位。模型结果不能改变发送者身份 |
| TX03 Agent 结果 | 业务处理结果、答复内容与依据、事项新版本、待发送任务 | 运行键唯一。重跑复用已提交结果。人工接管、暂停或新版本使旧结果失效。checkpoint 与应用提交分别持久化，恢复从应用操作记录核对，不假定两者原子 |
| TX04 接管 | 创建或更新唯一活跃待办、暂停对应事项、写首条通知任务 | 锁事项后处理待办。同一事项重复触发追加记录。通知失败不回滚待办。完结和交回检查版本并记录运营动作 |
| TX05 记忆、绑定与订阅 | 目标记录更新、影响范围的版本变化、关联任务取消或标为需复核 | 同规格只允许一个有效订阅。删除与纠正保留最小变更事实。批量清理可以异步执行，读取与最终发送立即校验当前有效性 |
| TX06 活动与计划 | 活动、计划或参与状态更新、任务生成或撤销 | 活动参与键由会员、活动、提交类型和周期组成。重复回传复用结果。已批准范围变更需重新确认 |
| TX07 领取任务 | 符合条件的任务、执行者、租约到期时间及领取代次 | 短事务领取后执行。提交结果时检查代次，旧执行者不能覆盖新结果。纯计算和可重放查询可在租约超时后恢复 |
| TX08 发送及结果 | 出站发送意图、尝试记录、最近一次资格核验；结果回填另一次事务 | 写入发送中后提交，再调供应商。仅在有明确证据时从待核实提升为已发送或已送达。崩溃或超时后发送中的任务转待核实。支持可靠供应商幂等键或状态查询时可用其核实，结果未知时不直接重发 |

任务记录至少包含种类、稳定业务键、可执行时间、有效截止、租约及代次、尝试数、状态、最后失败分类和关联对象。预约时间使用 UTC 存储，展示及业务日按 Asia/Shanghai 计算。领取按到期时间和稳定顺序。发送前重新检查活动、订阅、群、身份和权限。取消等更新若已提交且发送尚未取得执行许可，应阻止发送。已开始的外部请求可能无法撤回，实际结果须如实保存。外部恰好一次交付依赖供应商能力。本系统保证本地意图去重，并对不明结果进入核实流程。

数据库迁移与应用启动分离。Alembic 管业务表，checkpointer 的初始化及版本变更显式执行。迁移与测试优先使用专用数据库。跨模块对象依赖通过外键和唯一性约束表达，核心业务状态避免埋入不可查询的自由文本。

## 4. 接口、授权与可观测性

- [接口契约](API_CONTRACT.md)统一后台 HTTP、规范事件、外部业务端口、意图输出和幂等规则。供应商原生回调在接入工作包绑定，初始契约使用明确隔离的开发事件入口。
- 运营后台采用单运营服务端会话和同源请求，写操作校验 CSRF。运营账号凭据由本地配置及受控初始化提供，秘密从环境或本机非提交配置读取。会员身份绑定独立于后台会话。
- 渠道事件验签与防重放由相应适配器处理。业务查询以受信任身份、对象归属和渠道可见范围授权。外部密钥、原始订单明细与私人消息仅按用途保存，日志默认脱敏。
- 结构化日志记录 request_id、event_id、matter_id、run_id、job_id 中适用的标识、分支、延迟、重试、供应商结果及模型用量。运营后台展示可核对的资料、状态和失败原因。
- 源码公开版仅包含示例配置和虚构样例。运行日志、数据库备份、密钥、原始聊天及真实商家数据不进入公开仓库。
