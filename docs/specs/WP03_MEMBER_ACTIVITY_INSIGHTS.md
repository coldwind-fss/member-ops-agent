## 1. 交付目标与范围

运营可以在后台核对会员长期记忆、标签依据、个人需求和候选人群，也能管理轻量活动并查看群复盘。助手按身份和事项读取相关记忆。运营可纠正画像、修订品牌知识并验证新答复。面向候选人群的自动发送和补货订阅由 WP04 接入。

## 2. 行为和实施顺序

1. **记忆与画像**。按已确认会员身份写入明确偏好、事实事件和来源。临时预算、为别人选购的尺码只留在事项。推断以候选标签记录，由运营确认后可用于定向筛选。有效期按产品基线，纠正和删除立即影响读取及筛选。
2. **会员后台**。提供会员列表、详情、关键互动时间线、标签依据、人群筛选和预览。可以从群复盘跳转至具体证据和会员，查看命中、排除原因及人数。保存候选条件和确认范围。投递前复核在 WP04 实现。
3. **活动与互动**。运营创建、发布、暂停、恢复和取消轻量活动。会员经适当入口报名、打卡或提交问卷。校验有效期、会员资格、活动规则和重复提交。规则版本与参与结果可追溯。使用现有渠道或可用入口，后台能看参与进度。
4. **群分析和日报**。对获准范围的消息按群、时间和主题汇总。需要立即人工介入的明确投诉复用 F14。普通信号进日报和建议。可核对的个人信号进入候选记录，群级趋势保留在复盘中。
5. **知识编辑与纠错**。运营从问题、答复和使用版本进入纠错。按内容缺失、过期、误判、查询或权限错误分类。运营确认后发布有效版本。用原问题和改写样例对照，保留回答依据。
6. **契约与页面**。补充会员、记忆、筛选、活动、参与、复盘和知识管理接口。定义写入权限、版本、去重、保留期限和失败示例。后台主要页面是会员经营、活动管理、群复盘和知识管理。

## 3. 数据、权限与事务

涉及记忆、行为、候选与已确认标签、人群筛选、活动规则版本、参与记录、群反馈、日报、知识草稿、发布和纠错记录。关联依据可访问时可回看，到期时标明证据过期。删除画像与清理原始消息按各自保留规则。旧证据再次分析时不得重建已明确删除的记忆。应用按授权校验成员身份与个人资料，群级汇总不直接写入会员标签。TX05 和 TX06 负责纠正、删除与参与去重。与待执行触达的联动在 WP04 验证。

已确认的尺码、颜色和用途只在核验后的私密导购用于补齐缺失字段，当前显式条件优先。代购跳过个人默认值，图返回的业务上下文只持久化本事项自己的条件。基于长期记忆生成的待发答复携带绑定版本和画像版本。删除或更正后由 Worker 在发送前复核。

活动规则按版本存档，参与事务依据提交时的活动版本。报名、每日打卡和问卷使用不同的去重键。群复盘按上海业务日从已持久的信号按需生成，普通趋势与投诉分开。问卷正文在授权后入库，运营页面展示参与进度和脱敏记录。知识验证走与问答相同的检索与生成图，逐项记录实际回答和知识版本。

Worker 定期遮盖到期的消息原文，清理到期且不在人工处理中的事项上下文与快照。来源标识保留用于历史引用和重投去重。会员时间线与问卷内容按各自保留窗口清理。画像删除保留最小防重建边界，原消息按独立期限处理。

| WP03-02 更正、删除和身份解绑影响读取与候选筛选，重放旧消息不重建已删除条目 | PostgreSQL 业务集成 | 通过 |

| WP03-04 重复报名与同周期打卡返回已有结果，暂停和结束后拒绝新提交，参与统计准确 | 活动、入站 Worker 和参与记录 | 通过 |

| WP03-06 修订知识后新问答使用有效版本，旧回答保留当时版本，冲突资料按规则降级 | 知识发布、原问题和改写验证，WP01 冲突回归 | 通过 |
