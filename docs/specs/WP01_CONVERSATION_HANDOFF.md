## 1. 交付目标与范围

用本机测试适配器送入一条群咨询。系统持久接收，识别意图并找到正确事项，使用有效品牌资料回答，或把不能解决的问题交给唯一运营。运营在 Vue 后台能看到处理依据、待办和实际发送状态。

包含原生环境初始化、数据库迁移、API 和 Worker、本地后台登录、开发事件入口、会话列表与详情、人工待办及其结案、DeepSeek 意图识别和品牌问答两步 RAG。先用虚构品牌知识种子、测试消息渠道和测试通知端口演练。邮件渠道配置后可做独立发送验证。完整知识编辑、实际订单库存、活动、画像及真实渠道联调分别由后续工作包承接。

## 2. 行为与实施顺序

1. **工程底座**。建立 Vue 3、TypeScript 后台与 FastAPI/Worker 进程，复用本机 PostgreSQL。锁定依赖，提供样例配置和本机启动说明。Alembic 初始化应用表，单独初始化图快照表，使用专用测试库。
2. **事件入口**。按 OpenAPI 接收测试消息，验证测试凭据和连接，原子写入事件、消息及处理任务后返回 202。相同事件键同内容复用回执，内容冲突返回 409。普通闲聊的直接答复流程停止。群分析启用随 WP03。
3. **定位和分流**。根据可信渠道身份及引用确定候选范围，同一处理键顺序消费。DeepSeek 节点按契约输出结构化意图，应用校验归属、引用和允许动作。识别异常按限定重试预算处理。不同会员的回复各自锚定原消息。
4. **品牌问答两步 RAG**。按商品及别名、适用范围、分类、有效期和关键词检索当前资料，再把命中的片段交给 DeepSeek 生成答复。记录引用条目及版本。缺少型号时澄清，缺可靠依据时说明或交接。模型不能引用不存在或失效的资料。
5. **人工交接**。在同一事务写待办、事项接管状态和通知任务。直接提醒唯一负责人。后台可看「待跟进」「已处理」，可登记结果。需要助手续办时，提交明确的确认结果并交回该事项，应用创建续办任务。通知失败仍保留待办。
6. **发送和后台核对**。测试渠道记录真实可观察的测试发送结果。已受理、已发送、失败和待核实分开展示。领取、重启恢复、通知去重和旧结果拦截按技术基线执行。会话详情展示原消息预览、运行分支、回答引用及接管结果。

## 3. 数据、权限和契约

涉及运营会话、测试连接、入站事件、消息、事项与版本、知识条目及版本、图执行快照、任务、出站记录和人工待办。开发入口仅本机且默认关闭。后台会话和写操作遵循认证、CSRF、幂等键和版本校验。全套 10 个 HTTP 端点以 OpenAPI 为准。模型别名、SDK 兼容性、空输出与超时作为工程实测项。
