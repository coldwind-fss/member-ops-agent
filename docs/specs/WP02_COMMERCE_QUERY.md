## 1. 交付目标与范围

助手能解释公开商品和优惠，按本次需求做多轮导购，也能在验证身份后查询会员本人的订单、物流或权益。后台可见接口可用性、查询类别、资料依据和异常转交。按共享端口接入测试替身。真实身份验证和商家接口需要授权及独立联调。

本包以查询、推荐和可用入口引导为主。会员长期偏好在 WP03 接入。订阅登记和补货通知在 WP04 开放。在订阅能力尚不可用时，可以记录真实咨询供后续处理，避免提示会员已登记提醒。

## 2. 行为和实施顺序

1. **身份与可见性**。维护渠道身份到品牌会员的已验证关联和解绑。可信状态来自核验适配器。未绑定仍可使用公开问答。个人查询先确认身份，再检查目标归属和私密回复能力。
2. **适配器和结果类型**。建立商品、规格库存、订单物流、优惠权益等只读端口。测试替身覆盖成功、查无结果、未绑定、无权限、未配置、暂时失败及状态冲突。公开接口和个人接口分别应用必要授权。
3. **多轮选购**。使用当前事项的用途、预算和规格。缺关键信息时聚焦追问。比较商品时给出适用和限制，实时价格、库存按查询结果回答。工具循环有上限，完成、澄清、降级或接管后结束本轮。
4. **个人查询**。身份及会话都匹配后再调用业务端口。多笔订单在私密渠道请本人选择，继续查询时重新验证归属。无权和未找到使用相同的会员文案。已核验会员缺少私密会话时，优先提供官方入口。两种入口都不可用时将明确的个人查询登记到现有人工待办，条件式请求仍需核实条件。
5. **活动与权益**。公开规则使用有效知识与实时活动状态。个人资格要校验本人。资料冲突、活动已结束或查询异常时按各自状态处理。活动报名由 WP03 承接。
6. **后台和契约**。会话详情增加查询来源、结果类别和必要引用。后台能查看连接能力与绑定核验状态，敏感明细限于有权限的处理入口。进入实施前定义新增接口、适配器字段、异常示例和授权范围。

## 3. 数据与事务

商家业务源持有会员及订单主数据。应用新增渠道绑定、事项级查询槽位、查询依据和私密发送授权。导购的预算、用途、规格与代购对象仅在当前事项读取，数据按当前查询刷新。公开查询图每轮最多一次目录、两次库存和一次活动查询。私密订单与资格走应用分支，商家结果由确定性规则渲染。

查询调用在数据库短事务外进行。确认结果时锁定事项并复核版本，私密结果同时检查绑定版本。轨迹、查询依据、事项状态与答复出站记录一次提交。Worker 领取出站时再次检查事项及绑定版本，检查通过才记录开始发送。已开始发送的结果按实际回执核实。发送终态清除队列中的私密正文。后台查询依据仅含动作、结果类别、来源、时间和公开引用。落实 TX02、TX03、TX05 和 TX08 的适用部分。
