## 1. 目标和边界

在本机从空工程起步，跑通 Vue 后台壳、FastAPI、独立 Worker 和 PostgreSQL 的连接。下一单元可以在已固定的配置、迁移和启动流程之上实现运营会话。

本次包含环境检查、源码目录和依赖锁定、样例配置、空库迁移、API 和 Worker 的运行入口、两个健康接口、Vue 空工作台及本机启动说明。运营账号与登录归 S2，事件和任务领取归 S3，DeepSeek 与 LangGraph 的业务执行归 S4，知识问答和消息发送归 S5，人工待办归 S6。迁移基础设施在本单元验证，业务表随各单元新增。

## 2. 实施步骤与默认约定

1. **核对环境**。记录 Windows 上实际可用的 Python、Node.js、npm、Git 和 PostgreSQL 版本。当前 Python、Node.js 与 npm 命令可发现。确认 PostgreSQL 安装路径、服务状态、连接方式和专用开发、测试库权限。依赖兼容性在锁定前验证。
2. **建立工程入口**。按技术基线配置 Vue 3、TypeScript、Vite、FastAPI、SQLAlchemy、psycopg、Alembic 和测试依赖。API 与 Worker 使用独立入口和相同配置模块。工作区没有 Git 时，在开始实施后建立本地仓库，按范围配置忽略项。前端和 Python 分别保存可复现的依赖版本。
3. **配置与数据库**。提供样例配置。数据库 URL 走本机环境或忽略提交的文件。测试使用独立测试库，写入性测试不得回落到开发库。Alembic 通过显式命令执行，应用启动可以检查版本状态。空库升级流程须可验证，相关失败应给出修复提示。
4. **API 和 Worker 启动**。默认监听回环地址。FastAPI 提供契约中的两个健康接口。Worker 连接数据库后进入等待并支持正常停止。连接失败时输出可理解的错误并安全退出。此阶段 Worker 的可启动性和数据库连通可验证，业务任务领取随 S3 实现。
5. **后台壳与说明**。提供最小运营工作区和同源开发代理。页面能显示 API 存活及数据库就绪结果，异常时明确标示。提供 PowerShell 可执行的配置、迁移、运行、测试和停止步骤，以及常见失败说明。

默认使用原生本机进程和宿主 PostgreSQL。开发环境使用虚构样例。当前运行时具体版本以兼容性检查和锁定文件为准。需要安装 PostgreSQL、启动系统服务或创建数据库时，先核对现有环境与目标库，保留当前数据库和服务设置。

## 3. 接口、权限和可观察结果

| 接口 | 通过条件 | 异常结果 |
| --- | --- | --- |
| GET /api/v1/health/live | API 进程存活时 200，返回 status 为 ok | 进程退出或不可达由客户端连接结果反映 |
| GET /api/v1/health/ready | 专用持久依赖可用且数据库迁移到位时 200，返回 status 为 ok | PostgreSQL 不可达或迁移缺失时 503，返回 DEPENDENCY_UNAVAILABLE 与请求标识 |

健康接口仅返回必要状态，不返回凭据、详细配置或数据库内容。本机 API 和 Worker 启动日志分别标明可安全公开的环境标识及运行结果。模型或商家渠道未配置不影响本单元的 API 数据库就绪判定。
